# MATE 메모리의 스케일 표류

측정일 2026-09-10. 근거 스크립트: `scripts/diagnose_mate.py`.

## 현상

MATE의 메모리는 러닝 평균이다.

```
m_t = (init_emb + Σ_{i<t} z_i) / (w + t),     w = exp(log_init_weight)
```

`z`의 평균을 `μ`라 두면 `Σ_{i<t} z_i ≈ t·μ` 이므로

```
‖m_0‖ = ‖init_emb‖ / w        →        ‖m_∞‖ = ‖μ‖
```

**메모리는 "초기 사전분포"에서 "데이터 평균 임베딩"으로 이동한다.** 두 벡터의 크기가
다르면 그 차이가 곧 에피소드 내 스케일 변동이 된다. 헤드(또는 critic)는 같은 함수로
`t=1`의 입력과 `t=199`의 입력을 모두 처리해야 한다.

학습된 세계모델에서 예측과 실측이 일치한다.

| | 값 |
|---|---|
| `‖init_emb‖` | 17.131 |
| `w` | 37.802 |
| 예측 `‖m_0‖ = 17.131/37.802` | 0.453 |
| **실측 `‖m_1‖`** | **0.430** |
| 실측 `‖m_199‖` → 함의 `‖μ‖` | 1.138 → ≈1.27 |

## 다른 메모리와의 대조

`‖m_t‖`를 `t`에 대해 측정 (100만 에피소드로 20만 스텝 학습한 세계모델, 배치 16).

| t | MATE | GPT |
|---:|---:|---:|
| 1 | 0.430 | 5.782 |
| 10 | 0.372 | 5.804 |
| 50 | 0.732 | 5.809 |
| 100 | 0.956 | 5.784 |
| 150 | 1.079 | 5.811 |
| 199 | 1.138 | 5.837 |
| **최대/최소** | **3.09배** | **1.00배** |

GPT가 흔들리지 않는 이유는 Transformer의 최종 `ln_f` LayerNorm이다
(`policies/seq_models/trajectory_gpt2.py:550`). 구조가 스케일을 고정한다.

## 레포에 이미 있는 완화 장치는 하나뿐

전수 조사 결과 메모리 출력에 정규화를 가진 것은 GPT뿐이다.

| 메모리 | 출력 정규화 |
|---|---|
| GPT | `ln_f` LayerNorm — **있음** |
| LSTM | 없음. 다만 tanh 게이트로 `‖h‖`가 유계 |
| **MATE** | **없음.** `exp(log_init_weight)` 하나가 유일한 완화 장치 |
| SplAgger | 없음 |

`config_seq.normalize_inputs`는 이름과 달리 **입력만** 정규화한다
(`recurrent_head.py:124,127`): 인코딩된 관측과 전이 튜플에 `InputNorm`이 붙고,
**메모리는 정규화되지 않은 채 conditioner로 들어간다.** critic이 보는 두 입력 중
한쪽은 안정적이고 다른 쪽은 표류한다.

`use_pe`는 timestep 정보를 더해줄 뿐 스케일을 고치지 않는다.

## `w`는 완화 장치이지만 초기값이 나쁘다

`log_init_weight`의 초기값은 0, 즉 `w = 1`이다 (`mate_vanilla.py`). 그러면
200스텝 에피소드에서 분모가 `2 → 201`로 **100.5배** 움직인다. 학습이 진행되면
모델이 스스로 `w`를 키워 완화하지만, 얼마나 키우는지는 받는 신호의 밀도에 달려 있다.

| 학습 | `w` | `‖init_emb‖` | `‖m_0‖` | 200스텝 변동 |
|---|---:|---:|---:|---:|
| 세계모델 100만 데이터 λ=0 | 37.80 | 17.13 | 0.45 | **5.9배** |
| 세계모델 5만 데이터 λ=0 | 13.57 | 15.70 | 1.16 | 14.8배 |
| 세계모델 5만 λ=3 | 7.16 | 15.01 | 2.10 | 25.4배 |
| 세계모델 5만 λ=10 | 4.44 | 17.53 | 3.95 | 37.6배 |
| 세계모델 5만 λ=30 | 4.78 | 18.09 | 3.79 | 35.5배 |
| RL `nbaux_mate` (aux 회귀) | 4.40 | 14.90 | 3.39 | 37.8배 |
| RL `nbcpc_mate` (aux 대조) | 3.82 | 14.12 | 3.69 | 42.3배 |
| RL `nb_mate` (aux 없음) | 1.33 | 14.63 | 10.97 | 86.3배 |
| RL `mate_count_w1` | 1.11 | 14.58 | 13.14 | 95.3배 |
| **RL `nr_mate`** | **1.00** | 15.35 | 15.35 | **100.5배** |

두 가지가 읽힌다.

**RL은 `w`를 거의 못 키운다.** `nr_mate`는 초기값 `1.000`에서 한 발짝도 움직이지
않았다. `w`는 손실을 통해서만 학습되는 단일 스칼라인데, 세계모델은 스텝마다 40차원
× 200시점의 조밀한 예측 손실을 받는 반면 RL은 스칼라 TD 오차 하나뿐이다.
보조 손실을 켜면 `w`가 1.3 → 4.4로 오른다 — 조밀한 신호가 생기자 움직인 것이다.

**세계모델에서 λ를 키우면 `w`가 작아진다.** 손실을 케미스트리 칸으로 몰수록 MATE는
메모리를 더 불안정하게 둔다. 그리고 바로 그 설정에서 메모리를 아예 쓰지 않게 된다
(아래).

## 왜 문제가 되는가 — 메모리를 버린다

케미스트리 프로브(메모리만 detach해서 읽고, 에피소드 시작 대비 끝의 정확도 상승분).

| 학습 | 프로브 상승분 |
|---|---:|
| MATE λ=0 | **+0.247** (GPT +0.239보다 높음) |
| MATE λ=10 | **+0.000** |
| GPT λ=10 | +0.151 |

**MATE는 평범한 손실에서는 어떤 아키텍처보다 케미스트리를 많이 담는다.** 그런데 손실을
케미스트리 쪽으로 재가중하면 메모리를 통째로 포기한다. GPT는 같은 조건에서 유지한다.

해석: 표류하는 입력에 의존하느니 안정적인 `(o_t, a_t)` 단축만 쓰는 편이 최적화에
유리하다. 표류가 클수록(λ가 클수록 `w`가 작아지므로) 그 유인이 커진다.

## 기각된 대안 가설

같은 진단에서 함께 측정했다.

**그래디언트 희석 — 기각.** `∂m_t/∂z_i = 1/(w+t)`가 모든 `i`에 대해 같으므로
전이별 그래디언트가 균등하게 미미할 것이라 예상했으나, `z_i`는 이후 모든 시점의
메모리에 들어가 **누적**된다. 실측 최대/평균은 MATE 4.73, GPT 3.12로 **MATE가 오히려
더 집중적**이다.

**표현 한계 — 판정 불가.** 얼린 요약기 위에 새 헤드를 학습시켜 비교하려 했으나,
새 헤드를 모델과 다른 구조(GRU 순차생성 없는 MLP)로 만들고 3천 스텝만 학습시켜
20만 스텝 학습된 원래 헤드와 비교했다. 설계가 잘못되어 답이 되지 못한다.

## 별개의 병목: 희석

스케일과 무관하게 남는 문제. 무작위 정책 2000 에피소드 실측:

```
200스텝 중
  약 사용            171.8 (85.9%)
  그중 돌이 이동       31.6 (18.4%)   ← 케미스트리 정보
  trial 리셋            9.0
```

`t=199, w=37.8`에서 전이 하나의 기여는 `1/237 = 0.42%`, 정보 전이 32개를 합쳐도
**13.3%**다. 나머지 86.7%는 아무 일도 없던 전이가 차지한다. attention은 정보 있는
토큰에 가중치를 몰 수 있으므로 이 문제가 없다 — **평균 집계에만 선택적으로 작용한다.**

주의: "아무 일 없던 전이"를 버리는 것은 답이 아니다. 약을 썼는데 돌이 안 움직인
사실 자체가 케미스트리 정보다(간선이 막혔거나 이미 그 값이거나). 걸러내면 140개의
음성 증거를 버리게 된다.

레포에 전이별 가중치는 없다. MSC의 `gains()`는 **차원별** 스칼라이고
(`s ⊙ mean(z) = mean(s ⊙ z)`, 어느 전이가 중요한지 구분하지 못함), SplAgger는
균등 `mean`과 `cummax` 두 가지만 제공한다.

## 조치

`init_weight`를 지정할 수 있게 했다 (`mate_vanilla.py`, `configs/seq_models/mate_default.py`,
`scripts/train_world_model.py --init_weight`). 기본값은 기존과 같은 1.0이다.
세계모델에는 `--norm_memory`로 메모리 LayerNorm도 추가했다 (`world_model.py`).

검증 중인 스윕 (MATE + λ=10 + 100만 데이터, 10만 스텝, 다른 조건 동일):

| 팔 | 처방 | 초기 스케일 변동 |
|---|---|---:|
| `S_iw1` | 없음 (현행) | 100.5배 |
| `S_iw10` | `init_weight=10` | 19.2배 |
| `S_norm` | 메모리 LayerNorm | 1배 |
| `L_markov_w10` | 무기억 대조군 | — |

셋 다 무기억 대조군을 넘지 못하면 스케일이 아니라 희석이 병목이라는 뜻이 된다.

`w`를 키우는 것만으로는 부족할 수 있다. `w`를 키우면 `‖init_emb‖/w`가 작아져
`‖μ‖`와 오히려 더 벌어질 수 있다. 근본적으로 맞춰야 하는 것은
**`‖init_emb‖/w` 와 `‖μ‖` 의 비율**이며, 학습된 `w = 37.8`은 모델이 그 비율을
맞추려고 스스로 올린 값으로 보인다.

## RL 쪽 함의

RL 실험 전체가 스케일 변동 **34~100배**인 메모리 위에서 돌았다. 세계모델(5.9배)보다
6~17배 나쁜 조건이다. 이것이 RL 결과의 유일한 원인이라고 단정할 수는 없다 —
논문의 V-MPO(Transformer, 1e9 에피소드)도 정규화 점수 +0.070에 그쳤으므로 과제
자체가 어렵다. 다만 **MATE에만 불리하게 작용한 교란 요인이 통제되지 않았다**는 것은
확실하다.

RL은 `w`를 손실로 못 키우므로 초기값을 크게 주는 것이 특히 중요할 것으로 보인다.
세계모델 스윕에서 효과가 확인되면 같은 처방을 RL에 적용해 재실행하는 것이 다음 순서다.
